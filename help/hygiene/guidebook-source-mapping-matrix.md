> Internal review artifact. Source: Doug's "Value Realization Acceleration program – Guidebook" (NDA-sensitive, internal-only) mapped against the public draft "Advanced Data Lifecycle Management use cases and capabilities." This is not a public document and should not be linked from customer-facing content.

## Purpose and scope

This matrix tracks how themes, claims, patterns, and examples from Doug's guidebook were represented, adapted, excluded, or flagged for review while drafting the public Data Lifecycle guide. The current public draft stays scoped to a lifecycle capability decision hub (record delete, dataset expiration, Experience Event TTL, Pseudonymous Profile TTL). Broader value-realization or self-assessment content is captured as a future opportunity, not folded into the current draft.

## Likely current-draft updates

- Add a short, prose (not table) reminder that non-production sandboxes should follow the same TTL discipline as production — avoid replicating full production data into dev/test without a defined use case. Keep this general; do not cite the 10% Addressable Audience figure without SME confirmation.
- Fold in the general practice of applying data minimization at ingestion (only bring in data tied to an active use case) as a sentence in the "Why manage your data lifecycle" section — this reinforces the existing message rather than adding new scope.
- Consider naming a specific review cadence ("review usage regularly, such as weekly") in "Plan your retention strategy," but confirm the cadence with an SME first since the source is an internal recommendation, not a published default.
